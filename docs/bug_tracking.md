# Bug tracking

Known issues in the codebase. Each row is a kebab-case slug, a one-line description, optional file:line, and (where useful) a brief note on the intended fix. Same conventions as `status.md` — resolve by fixing in code, then strike the row (or remove it). If a bug ends up reshaping a feature, update the feature row in `status.md` instead of carrying both.

**No `// status: bug-…` markers in code.** Unlike feature slugs (which are stable references future readers may want to grep for), bug slugs are short-lived: once the row here is struck, the slug stops being meaningful. Tagging fixes inline just clutters the source. The git history and this file are enough.

## Bug→code links (`manifests-in::` / `verifies-fix::`)

Bug rows can carry **typed code links**, making bugs the second authored node kind on the spec
engine (after spec entries — see `status.md` "Spec→code links"; same `links.json` baseline, same
reconcile/drift/ack tooling). The authoring form is inline: a row IS the bug's whole entry, so the
link fields go in its Notes cell, anywhere in the row line — no `[slug]` anchor line, no per-bug
file:

`| ~~`bug-example-row`~~ | n/a | RESOLVED … manifests-in:: [[code:…/affected_fn]] · verifies-fix:: [[code:…/tests/regression_test]] |`

- **`manifests-in::`** — the symbol where the bug lives (or lived): the claim "this code carries
  this bug". Authorable the day the bug is filed.
- **`verifies-fix::`** — the regression test that vouches for the fix; authored when the bug is
  resolved, alongside striking the row.
- **Reconcile treats the bug slug as the anchor** for any link fields found on its row (struck
  rows included), and each `rel::` token claims the `[[code:hiker/…]]` links between it and the
  next token. Both relations are body-level claims, so the relation floor pins them at **Code**
  resolution (the `verifies` rationale: a coarser dial on a body claim refutes itself); the doc's
  frontmatter altitude never coarsens them. These relations exist only on bug rows — they are
  never authored as anchored link lines under spec entries. [tracker-relation-links]
